# 전처리 명세: KOSIS 통계표 → 계산·LLM 입력

- plan: docs/plans/20261020-stage1-table-summary/PLAN.md (rev 3)
- status: DRAFT rev 3 (10/22 단일 표 실제 응답으로 검증 후 확정)

전처리의 목표는 "같은 기준으로, 출처를 잃지 않고" 정규화된 전체 셀 자료를 만드는 것이다.
질문에 답할 대상 행과 계산에 필요한 근거 행은 이 정규화 자료에서 따로 고른다 (R6).

## 1. 자료형

입력 자료형은 베이스라인 PLAN의 **TableInput(TableMeta + Cell)** 을 그대로 쓴다. 필드의 필수 여부·자료형·원본/파생 정의는 그 문서 한 곳에만 둔다.
전처리는 Cell에 아래 파생 필드를 추가한다. 원본 필드(item, dims, dim_codes, period_raw, value_raw, unit, source_ref)는 바꾸지 않는다.

| 파생 필드 | 자료형 | 규칙 | 예 |
| --- | --- | --- | --- |
| period | str | R3 | 2024 / 2024-01 / 2024Q1 |
| period_kind | Y / M / Q / H | R3 | Y |
| value | float 또는 None | R4 | 1234567.0 |
| value_flag | ok / missing / suppressed / provisional / unparsed | R4 | ok |
| measure_kind | count_stock / count_flow / ratio / average / index | 단위·항목명으로 추정, 표별 수동 지정표로 덮어씀 | count_stock |
| is_total | dict[분류명, bool] | R2 | {성별: false, 연령: false} |
| level | dict[분류명, leaf / aggregate / total] | R2 | {연령: leaf} |

source_ref는 원본 코드가 있으면 tbl_id+항목+분류코드+시점, 코드가 없는 CSV면 file_sha256+원본 행 번호다 (베이스라인 PLAN 정의).

## 2. 규칙

**R1. 분류 코드 → 이름:** KOSIS JSON의 C1_NM.. 와 분류명(C1_OBJ_NM..)을 dims로, 코드값은 dim_codes로 보존한다. CSV에 code:<분류명> 컬럼이 있으면 같은 방식.

**R2. 계/소계:** "계", "합계", "전체"는 total, "소계"와 묶음 구간(예: 15~64세)은 aggregate, 나머지는 leaf로 표시한다.
합계·구성비 계산은 같은 분류 수준의 leaf만 쓰고, 표에 total이 있으면 직접 합산 대신 total을 쓴다.
계산한 leaf 합과 total이 다르면 경고를 남긴다(반올림·비공개 셀 때문일 수 있음).

**R3. 시점:** YYYY, YYYYMM, YYYYQn 등을 period + period_kind로 통일한다. period_raw는 유지한다.
추이·증감률은 같은 period_kind끼리만 계산한다.

**R4. 값과 결측:** value_raw → value. "-", "x", "…", 빈 값은 None + value_flag로 구분하고, 해석할 수 없는 문자열은 unparsed.
잠정치·추정치 표시가 있으면 provisional로 남기고 답변 한계에 표기한다.

**R5. 단위:** 셀의 unit이 기준이다. "천명" 등 배수 단위는 환산하지 않고 그대로 두되, 비교·합산 전 단위 일치를 검사한다.
단위가 다르면 계산하지 않고 "비교 불가" 사유로 넘긴다. %와 수량은 합산하지 않는다.

**R6. 대상 행과 근거 행 분리:** 필터링은 두 번 한다.
1. **계산 계획 먼저:** 질문 유형에 따라 분자·분모·비교 기준 시점을 정한다 (예: "2024년 여자 인구 비중" → 분자 = 2024·여자, 분모 = 2024·성별 total).
2. **대상 행:** 질문 조건(item, dims, period)으로 답변 대상 셀을 고른다.
3. **근거 행:** 계산 계획에 필요한 셀을 정규화 전체 자료에서 따로 조회한다. 대상 행 필터 결과에서 고르지 않는다.
- 조건에 맞는 값이 표에 없으면 빈 결과 + "표에 없는 조건" 사유를 반환한다(가까운 값으로 대체 금지).

**R7. 크기 제한:** 행 수가 아니라 모델 토큰 한도(`max_input_tokens`)로 판단한다. 계산은 근거 행 전체로 하고, LLM에는 facts와 대상 행만 넘긴다.
그래도 한도를 넘으면 잘라 넣지 않고 input_too_long으로 처리한다.

**R8. 합산 가능 여부:** count_* 이고, 단위·시점·나머지 분류가 같고, 같은 수준의 leaf이며, 합산에 쓰는 셀이 결측이 아닐 때만 합산.
count_stock은 시점 간 합산 금지, count_flow는 기간이 빠짐없을 때만. ratio·average·index는 합산·단순 평균 금지.

**R9. 구성비 분모와 결측:**
- 분모 우선순위: (1) 같은 표·시점·단위·나머지 분류의 total 셀, (2) 없으면 R8을 만족하는 leaf 합.
- leaf 합을 분모로 쓸 때는 그 분류의 **전체 leaf 범주**(정규화 자료에 있는 해당 분류의 모든 leaf)를 포함해야 한다. 질문으로 좁힌 일부 행의 합을 전체로 간주하지 않는다.
- 결측 처리:
  - 분자가 결측 → 계산 불가
  - total 분모를 쓰는데 total이 결측 → leaf 합으로 대체 시도, 그것도 안 되면 계산 불가
  - leaf 합 분모를 쓰는데 필요한 leaf 중 하나라도 결측 → 계산 불가
  - 분자와 total이 모두 확인되면, 계산에 쓰지 않는 다른 leaf의 결측만으로 거부하지 않는다
  - 분모가 0 → 계산 불가 (사유: 분모 0)
- 분모 fact(원본 셀 source_ref 또는 합산 대상 source_ref 목록)를 facts에 넣어 답변·검증에서 함께 쓴다.

## 3. LLM 입력 직렬화 (1차 PLAN FR-012, 단일 표 E2E 게이트 통과 후 실험)

초기 기본값은 A(마크다운 표). 모든 형식은 같은 메타 헤더를 앞에 둔다: 조사명 / 표명 / 작성기관 / 기간 / 출처. 단위는 셀마다 보이게 한다.

| 형식 | 모양 | 기대 장단점 |
| --- | --- | --- |
| A. 마크다운 표 | 행=분류, 열=시점, 단위 열 포함 | 짧고 사람이 보기 쉬움, 다단 분류에서 열이 늘어남 |
| B. JSON 레코드 | 셀마다 {dims, period, value, unit} | 구조 명확, 토큰 많음 |
| C. 문장형 | "2024년 남자 30~34세 인구는 N명" | 모델이 그대로 인용하기 쉬움, 길어짐 |

## 4. 테스트 케이스 (규칙별 최소 1개)

- [ ] R1: KOSIS JSON의 C1_NM/C1_OBJ_NM이 dims로, 코드가 dim_codes로 보존된다
- [ ] R1: 코드 없는 CSV의 source_ref가 file_sha256+행 번호로 만들어진다
- [ ] R2: 성별 계 + 남/여가 있는 표에서 합계가 중복되지 않는다
- [ ] R2: 연령 묶음 구간이 leaf 합산에서 제외된다
- [ ] R3: 월·연 시점이 섞인 입력에서 추이가 같은 주기로만 계산된다
- [ ] R4: "-", "x" 셀이 0이 아니라 None으로, 해석 불가 문자열은 unparsed로 처리된다
- [ ] R4: 전처리 후 value_raw·unit·source_ref가 그대로다
- [ ] R5: 단위가 다른 두 항목 비교 요청이 "비교 불가"로 넘어간다
- [ ] R6: 표에 없는 연도 요청이 빈 결과 + 사유를 반환한다
- [ ] R6: "2024년 여자 인구 비중" — 대상 행을 여자로 좁혀도 분모로 성별 total이 선택된다 (여자 행만으로 100%가 나오는 오류 재현 테스트)
- [ ] R7: 토큰 한도를 넘는 입력이 잘리지 않고 input_too_long이 된다
- [ ] R8: % 항목 두 개의 합산 요청이 거부된다
- [ ] R8: 연말 인구를 여러 해 합산하는 요청이 거부된다
- [ ] R9: total이 있는 표에서 분모로 total이 쓰인다
- [ ] R9: total 분모 사용 시, 계산에 쓰지 않는 다른 leaf가 결측이어도 계산된다
- [ ] R9: total이 없고 leaf 하나가 결측이면 계산 불가
- [ ] R9: total이 없을 때 leaf 합이 전체 leaf 범주를 포함한다 (일부 범주만으로 분모를 만들지 않음)
- [ ] R9: 분모 0이면 계산 불가
