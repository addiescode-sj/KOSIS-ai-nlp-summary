# 텍스트 생성·요약 후보 모델 선정

태스크: T1-16 · Linear KOS-53 (구 T1-29. 계획과 옵션 비교: [plans/T1-16-candidates.md](../plans/T1-16-candidates.md), 선택: 옵션 A · HCX 모델끼리 비교)
작성일: 2026-10-21 · 갱신: 2026-10-22 · 상태: 후보와 비교 방법 확정, **사전 비교(파일럿) 완료 · 골든셋 정식 비교 전**

## 1. 역할과 전제

- 이 모델이 하는 일은 **질문 해석과 설명 문장 생성**이다. 수치 조회·계산은 코드가 한다 (CLAUDE.md 2장). 예외는 B0 하나로, B0에서는 표 전체를 모델에 넣고 모델이 직접 답한다.
- 공식 점수(B0 → B4)는 HCX로 잰다 (docs/workflow.md 2장). 따라서 이 문서는 "실전 1에서 어떤 HCX 모델·설정을 기본으로 쓸지"를 정한다.
- 모델 역할이 B0와 B3 이후에 다르므로, 같은 결론이 두 시점에 모두 맞는다고 가정하지 않는다. B0에서 한 번 비교하고, 파이프라인 결합 후 개선 회차(T1-13·T1-14)에 다시 확인한다.

## 3. 선정 기준과 측정 방법

| 순위 | 기준 | 측정 | 사용하는 실패 태그·지표 |
| --- | --- | --- | --- |
| 1 | 숫자 보존 | 답변의 값·단위·시점·분류가 정답과 근거 셀에 맞는가 | `hallucinated_value`, `wrong_unit`, `wrong_period`, `wrong_category`, `calc_error` 건수 |
| 2 | 거절 정확도 | 불가 문항은 거절하고, 가능한 문항은 거절하지 않는가 | `missed_refusal`, `unnecessary_refusal` 건수 |
| 3 | 형식 준수 | B2 질문 분석·B4 검증용 JSON 출력을 지키는가 | JSON 파싱 성공률 (B2 도입 후 측정) |
| 4 | 한국어 문장 품질 | 자연스러움, 단위·출처 표기 | 사람 판정 PASS/PARTIAL, `missing_source` 건수 |
| 5 | 운영 | 응답 지연, 호출 비용, 최대 입력 길이 | 문항당 평균 지연(초), 호출 수, 최대 토큰 (B0는 표 전체를 넣으므로 표 크기가 한도 안인지) |

채점 기준과 실패 태그 정의는 [golden-set-guide.md](golden-set-guide.md) 4·5장을 따른다.

## 4. 비교 절차

1. 고정: 골든셋 버전(v1), 원본 데이터 sha256, 프롬프트, 전처리, temperature 0, runs 1. **모델 설정만 바꾼다.**
2. M1 → M2 → M3 순서로 골든셋 v1 전체(약 17문항)를 실행한다. 호출 수는 약 17 × 3 = 51회.
3. 실행마다 manifest.json에 모델 이름, thinking 설정, 데이터 해시, 골든셋 버전을 남긴다.
4. 사람이 판정하고(eval.review), scorer로 집계한다. 판정자는 어떤 모델의 답인지 모르는 상태로 보는 것이 좋다 (가능하면 모델 이름을 가리고 섞어서 판정).
5. `eval-history.md`에 모델마다 한 줄씩 기록한다. 버전 칸은 `B0·M1`처럼 쓴다.

   | 버전 | 날짜 | 골든셋 버전 | 데이터 해시 | 모델 | PASS / PARTIAL / FAIL | 주요 실패 태그 | 바꾼 것 |
   | --- | --- | --- | --- | --- | --- | --- | --- |
   | B0·M1 | | v1 | | HCX-007 thinking 끔 (temp 0, runs 1) | | | 모델 설정만 |

## 5. 결정 규칙 (초안, 팀 합의 필요)

1. `hallucinated_value`가 1건이라도 나온 설정은 기본 모델 후보에서 뺀다. 숫자를 지어내지 않는 것이 이 프로젝트의 첫 번째 규칙이다.
2. 남은 설정 중 PASS 수가 가장 많은 것을 고른다.
3. PASS 차이가 1문항 이하이면 같은 수준으로 보고, 지연·비용이 낮은 쪽을 고른다. 17문항 규모에서는 1문항 차이를 의미 있는 차이로 보기 어렵다.
4. PASS가 같아도 `unnecessary_refusal`이 더 많은 설정은 낮게 친다. 거절로 점수를 올리는 것을 막기 위해서다.
5. 모든 설정이 1번에 걸리면 모델이 아니라 파이프라인 문제로 보고, B3(코드 계산) 적용을 앞당기는 근거로 기록한다.

## 8. 비교 결과

### 8.1 사전 비교 (파일럿, 2026-10-22)

골든셋이 준비되기 전에 후보 간 차이가 있는지 먼저 확인하려고 돌린 소규모 비교다. 4절의 정식 비교를 대신하지 않으며, `eval-history.md`에도 올리지 않는다.

**조건**

- 표: 인구동향조사 · 시군구·성·연령별 출생(DT_1B8000F) 중 전국 출생아수·합계출산율 2022~2024년 3행. B0처럼 표 전체를 프롬프트에 넣었다.
- 문항: 12개. 답변 가능 8개(T1 단순 조회 2, T2 증감·증감률 4, T5 최솟값 1, 합계 1), 답변 불가 4개(N1 없는 연도 2025년, N2 없는 분류 서울시·남아, N5 원인 질문).
- 고정: 같은 시스템 프롬프트, temperature 0, 문항당 2회 실행. 모델 설정만 바꿨다. 모델당 24개 답변, 총 72회 호출.
- 채점: 정답 수치 포함 여부·거절 여부를 자동으로 판정한 뒤, 오답으로 나온 답변은 모두 사람이 원문을 보고 다시 판정했다(LaTeX 표기 `717,\!557` 오판 등 정정).

**결과** (모델당 24개 답변)

| 후보 | PASS / PARTIAL / FAIL | hallucinated_value | 숫자 관련 오류 합계 | 거절 오류 (missed / unnecessary) | 출처 표기 | 평균 지연(초) | 평균 토큰 | 비고 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| M1 HCX-007 thinking 끔 | 20 / 0 / 4 | 0 | 2 (`calc_error`) | 0 / 2 | 16/24 | 1.7 | 314 | 2022→2024 증감률 −4.35%를 −4.23%, −4.32%로 계산. 합계출산율 차이 질문을 "단위 때문에 계산 불가"라며 거절 |

**해석**

- 거절 판단은 세 설정 모두 정확했고, 답변 불가 문항에서 값을 지어낸 경우(`hallucinated_value`)는 없었다.
- 차이는 **계산**에서 났다. 모델이 표를 읽고 직접 계산하는 B0 조건에서는 M2 > M1 > M3 순이다. M3는 계산을 맡으면 안 되는 수준이다.
- M2는 정확도가 가장 높지만 지연이 M1의 약 6배, 토큰이 약 2.7배다. 또 제공 데이터 밖의 정보(외부 지식, 생성 링크)를 덧붙이는 경향이 있어 프롬프트에 금지 문구가 필요하다. 출처 링크는 모델이 만들지 않고 코드가 붙이는 것이 맞다(CLAUDE.md 2장).
- M3의 단순 조회·거절 정답률과 속도를 보면, 숫자를 코드가 계산하는 B3 이후 "설명 문장만 쓰는" 역할에서는 여전히 후보가 될 수 있다. 7절 계획대로 개선 회차에서 다시 확인한다.

**잠정 판단** (5절 규칙 적용): 1번 규칙(`hallucinated_value`)에 걸린 설정은 없다. 2번 규칙(PASS 최다)에 따라 B0 기본 설정은 **M2 HCX-007 thinking 켬**이 앞선다. M1과의 PASS 차이는 2개로 3번 규칙(1문항 이하 차이)에 해당하지 않는다. 단, 표 1개·12문항 규모라 정식 비교로 확정한다.

**한계**

- 표 1개(3행), 12문항으로 범위가 좁다. 긴 표, 결측(N6), 단위 불일치(N4), 분류 범위 불일치(N3)는 다루지 않았다.
- 자동 채점은 키워드·숫자 문자열 매칭이라 오판이 있었고, 사람 재판정은 1인이 모델 이름을 아는 상태에서 했다(4절 블라인드 판정 아님).
- thinking 켬에서 temperature 0이 실제로 적용되는지는 확인하지 않았다(7절 미확인 사항).
- 호출 설정: HCX-007은 `maxCompletionTokens` 1024(끔)·5120(켬, `thinking.effort: low`), HCX-DASH-002는 `maxTokens` 1024. CLOVA Studio v3 chat-completions API.
