# KOSIS AI 프로젝트: 목적과 로드맵

## 목적
사용자가 통계 수치를 정확히 이해하도록 자연어 요약과 시각화를 제공한다. 이후에는 질문에 맞는 통계표를 찾아 올바른 데이터로 연결한다. 수치·조건의 정확성을 우선하고, 기술은 평가 근거로 선택한다.

## Phase 1 | 10/26-10/28
목표: 요약 모듈·평가 결과·한계 문서를 제출하고, 비교 가능한 실측에 근거한 개선 근거를 최소 2건 남긴다.

### 비교 가능한 평가 확보
같은 62문항·같은 모델·같은 평가 조건에서 기준 방식(B0)과 C 파이프라인을 비교한다. 수정 전 결과를 먼저 보존하고 사람 판정을 완료한다. 자연어 품질 0-2점 항목을 추가해 평균과 0점 사례를 남긴다.

### 정확도 개선과 원인 확인
‘1인’, ‘65세’ 등 분류 라벨 숫자의 검증기 오탐을 수정하고, 오류 주입으로 실제 숫자 오류 검출이 유지되는지 확인한다. 같은 조건에서 재측정한다. 남은 분류 조건 오류·조건 임의 가정·되묻기 실패는 수정 또는 한계로 분류한다.

### 설명 가능한 평가·제출물
판정·슬롯 추출·계산·검증·재생성·템플릿 대체의 단계별 로그와 실패 건수를 남긴다. 로그 단위는 Phase 2의 OpenTelemetry span으로 옮길 수 있게 정한다. 골든 정답에서 질문 유형·항목·기간·분류의 슬롯 정답을 도출해 필드별 정확도를 측정한다. 한계·개선사항·Phase 2 이월 범위를 정리하고, 기존 멘토 질문의 아키텍처·스키마 필드·골든셋 분포·메트릭·실패 유형·개선 우선순위에 답한다.

### 진행 순서
평가 조건 고정·수정 전 기록 → 자연어 품질을 포함한 사람 판정 → 오탐 수정·재측정 → 단계별 로그·슬롯 평가(병행 가능) → 잔여 오류 분류 → 한계·제출물 정리.

## Phase 2 초반 | 10/28-10/31
목표: 질문에 맞는 통계표 검색 기준선을 만들고, 이후 구현에 사용할 기술을 근거로 선택한다. 이번 구간은 검색 기준선과 기술 검증까지를 다룬다.

### 검색 입력과 평가셋
표명·조사명·기관·수록기간·주기·분류·항목·링크를 정리한다. 검색 평가 질문은 100건 이상으로 구성하고, 직접 표명·개념어·복수 조건·모호함·주기 조건·답 없음의 유형별 분포를 남긴다. 답 없음은 약 25%로 계획한다. 멘토 PoC 실패 사례인 ‘주민등록 총인구수’, ‘최근 3개월 출생아수’도 포함한다.

### 검색 기준선과 조건 검증
기존 평가 도구를 검색용으로 확장하고 LangChain 검색기로 BM25 기준선을 측정한다. 정답이 상위 1·5·10개에 포함되는 비율(Hit@1/5/10), 정답 순위 지표(MRR), 답 없음 판정의 정밀도·재현율·F1, 유형별 결과·지연·호출 수를 남긴다. 표 선정 전에 기간·주기를 확인하는 후보 필터 규칙 초안을 만든다.

### 짧은 기술 검증과 선택
추적 도구는 OpenTelemetry + Jaeger로 확정했으므로 선택 절차는 두지 않는다. 반나절 동안 Phase 1 단계별 로그를 span으로 옮기는 계측 설계(span 단위·속성, 검색 단계 포함)를 정리한다. LLM 토큰·비용은 Jaeger가 아니라 OpenTelemetry에서 별도 계측한다. 모델은 실행 환경·사용 가능 여부·사용 승인을 먼저 확인한 뒤 반나절 동안 Gemma 4 31B와 HCX를 같은 슬롯 평가로 비교한다. 필드 정확도·JSON 첫 시도 통과율·지연의 비교표 1건과 채택 판단을 정리한다.

### 이 구간의 검토 산출물
검색 메타데이터·질문 분포, BM25 평가 결과, 기간·주기 필터 초안, OpenTelemetry 계측 설계, 모델 비교표와 채택 판단.
