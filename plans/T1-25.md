# T1-25 골든셋 복합 통계 문항 증강 (계산·파싱 고도화용)

## Goal
- 완료 기준 (TASK.md 그대로): n개 연도 종합(평균·누적·기간 비교·격차 변화·연속 증감·전년 대비 최대 등)과 어려운 기간 표현을 담은 문항을 20건 이상 추가한다. 정답은 Parquet 셀과 derivation으로만 채우고 oracle PASS를 확인한다. 현재 C 파이프라인이 처리하지 못하는 연산을 유형별로 기록해 고도화 대상으로 넘긴다
- Baseline (`eval/golden/stat_golden.jsonl` 40 + `stat_golden_edge.jsonl` 22 = 62문항):
  - 3개 이상 시점을 정답으로 요구하는 문항 **2/62**, 3개 이상 fact를 묶는 derivation **2/62**
  - 계산 모듈(`kosis_chat/compute/engine.py`)이 처리하는 연산: 값·추이(처음↔끝 두 시점의 차·증감률)·비교(두 칸)·비중·최대최소 5종.
    n년 평균·누적합·기간 평균 비교·격차 변화·전년 대비 증감의 최대·연속 증감 횟수·처음으로 기준을 넘은 해는 **없다**.
  - 파싱(`kosis_chat/judge/question.py`)이 읽는 기간 표현: `YYYY`, `YYYY년 M월`, `A~B`, `A부터 B`, `A년 이후`, `최근 N년`, `최근`.
    `2010년대`, `코로나 이전 3년`, `5년 전과 비교`, `지난 10년`, `상반기` 등은 **못 읽는다**.

## Idea
1. 연산 카탈로그를 정한다. 각 연산마다 표 1개 이상에서 문항 2개 안팎을 만든다.

   | id 접두어 | 연산 | 정답 표현 (derivation, + - * / 만) | 예시 질문 |
   |---|---|---|---|
   | `AVG` | n년 평균 | `(f1 + … + fn) / n` | 2019~2023년 서울 출생아 수의 연평균은? |
   | `SUM` | 누적합 | `f1 + … + fn` | 2020~2024년 전국 혼인 건수를 모두 합하면? |
   | `PAVG` | 두 기간 평균 비교 | 평균 2개 + 차 + 변화율 | 2010년대 전반과 후반 출생아 수 연평균 차이 |
   | `GAP` | 두 대상 격차의 변화 | `(f4 - f3) - (f2 - f1)` | 서울과 경기 인구밀도 격차는 2015년보다 2025년에 얼마나 줄었나 |
   | `GRW` | 두 대상 증감률 비교 | 증감률 2개 + 차(%p) | 부산과 대구 중 2015→2024 출생아 감소율이 더 큰 곳 |
   | `SHR` | 구성비 변화(%p) | 비중 2개 + 차 | 1인 가구 비중은 2015년보다 2024년에 몇 %p 올랐나 |
   | `VSA` | 최근 값 ↔ n년 평균 | 평균 + 최근 값 + 차·비율 | 2024년 혼인 건수는 직전 5년 평균보다 얼마나 많나 |
   | `MON` | 월 → 기간 합 | 월 셀 합 | 2024년 상반기 서울 혼인 건수 |

   기간 표현 문항(`PRD`): 연산은 단순(값·추이)하게 두고 기간 표현만 어렵게 한다. `2010년대`, `코로나 이전 3년`(2017~2019), `5년 전과 비교`, `직전 5년`, `상반기`. 정답 셀은 표현을 풀어낸 기간.
   - **연산 대상은 건수 지표(출생아 수·혼인 건수·사망자 수)만** 쓴다. RefusalReason `not_aggregatable`의 정의가 "시간에 걸친 비율·평균·저량의 합산"이므로, 합계출산율·인구밀도·가구 수(저량)의 기간 합·평균은 답할 문항이 아니라 거절 문항이다.
   - **반올림 규칙**(채점 허용오차가 골든 `round`로 정해지므로 엔진 규칙에 맞춘다): 차는 입력의 소수 자릿수, 증감률·비중·배수는 1자리(`PERCENT_DIGITS`), 평균은 1자리, 합은 0자리.
2. 거절·되묻기 문항도 복합 연산으로 만든다(`REF`): 기간 일부가 표에 없는 n년 평균(`no_period`, 예: 1인 가구 표는 2015년부터), 합계출산율을 여러 해 더하기·가구 수(저량) 누적합(`not_aggregatable`, 정의 그대로), 기준 시점이 모호한 “작년 대비”(default_allowed, 마지막 시점 명시).
3. T1-19 방식을 그대로 쓴다. spec(`eval/golden/complex_spec.json`)에 셀 ref와 derivation만 쓰고, `scripts/build_golden_edge.py --spec … --out eval/golden/stat_golden_complex.jsonl`로 Parquet 값과 계산값을 채운다(손으로 쓴 숫자 0). `golden_to_parquet.py`로 oracle scope를 채운다.
4. 측정: (1) oracle 채점 PASS, (2) 오류 주입 검출, (3) **현재 C 파이프라인을 mock 백엔드로 신규 문항에 실행** → 처리한 문항 수 = 고도화 전 기준선(추정하지 않고 실측). mock은 **규칙 파싱 + 계산**만 잰다. 규칙이 못 읽은 문항은 HCX 분류 보완(analyze_fill) 대신 mock 응답을 받아 예비 챗봇으로 빠지므로, HCX 보완 경로는 이 기준선에 들어가지 않는다.

## Option A — 문항 id 접두어로 연산 묶기 (계약 변경 없음)
- 접근: 위 카탈로그로 22~24문항을 `stat_golden_complex.jsonl`에 추가. 문항 id에 연산을 넣는다(`S-CX-AVG-01`, `S-CX-GAP-01`, `S-CX-PRD-01`, `S-CX-REF-01`). `eval/harness.py`의 분해에 id 접두어 그룹(`op=AVG`)을 추가한다(몇 줄 + pytest 1개). `GoldenItem`은 그대로.
- 예상 성능 향상: 3개 이상 시점 문항 2/62 → **약 18/86**, 3개 이상 fact derivation 2/62 → **약 14/86** (카탈로그 문항 수에서 셈). 현재 C 파이프라인 처리 수는 **추정하지 않고 mock 실측**으로 기록. 근거: engine에는 n년 평균·누적합·두 대상 증감률·두 시점 비중 차가 없다(`_trend`는 한 칸의 처음↔끝, `_share`는 한 시점) → 답할 문항 대부분이 FAIL일 것으로 보지만 수치는 실측으로 확정.
- 실질 반영 이점: 데이터 정확성·질의 이해 평가 범위 확대. 매 실행 리포트에 연산별 PASS/FAIL이 나와 계산 고도화 전→후(`op=AVG 0/3 → 3/3`)가 자동으로 남는다. T1-24 회귀 게이트와 같은 골든 형식이라 그대로 비교된다.
- 비용·리스크: 반나절 + 1시간, LLM 0. 문항당 연산 태그가 하나뿐이다(기간 표현은 PRD 문항으로 따로 둬서 해결).

### 범위에서 뺀 것
- 연평균 증가율(CAGR): 거듭제곱이 필요한데 채점기 `evaluate`는 + - * /만 지원한다. 채점기 변경은 T1-24 기준선을 깨므로 이번 범위에서 빼고 한계로 기록한다.
- **연속 증감(`streak`)·처음 기준을 넘은 해(`threshold_first`)·전년 대비 증감 최대(`max_yoy`)**: 지금 채점기로는 공정하게 판정할 수 없다. note fact는 채점하지 않고, 구간 셀이나 연도별 차를 전부 내보내면 "몇 년 연속"이나 "최대"를 계산하지 않아도 PASS가 난다. 반대로 맞는 답의 "5년 연속"·"1명"은 기간이 아닌 숫자라 unsupported_claim이 된다. 정답 연도·횟수를 채점하는 필드(예: `answer_period`)가 채점기에 생길 때까지 빼고, T1-23/T1-14 후속으로 넘긴다.
- 질문 속 "5년"·"3년" 같은 숫자를 답 문장에 그대로 쓰면 지금 채점기는 근거 없는 숫자로 센다(T1-13 라벨 숫자 오탐과 같은 종류). 골든은 그대로 두고 T1-13 수정에 맡긴다.
- 여러 표를 넘나드는 질문(예: 출생아 수 ÷ 인구): `GoldenItem`이 표 1개라 표현 불가(T3-05로).
