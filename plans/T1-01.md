# T1-01 EDA — 대상 통계표 프로파일링

## Goal
- 완료 기준 (TASK.md 그대로): 대상 통계표 3~5개 구조·단위·결측 기호·분류 체계 프로파일링 → `docs/eda.md`
- Linear: KOS-9 (담당 전민기, 마감 10/22) · 브랜치 `T1-01-eda-kos-9`
- Baseline: baseline 없음 (실데이터 프로파일 없음. B0 전처리 규칙 R1~R9는 가상 표로만 검증됨)

## Idea
1. **입력 확인 (10/21 확인됨)**: 팀에서 공유받은 `data/*.csv` 14개는 수치가 아니라 통계표 목록(2,364행, UTF-8 BOM, 열: 통계조사명·기관ID·통계표명·통계표ID·수록기간·단위·경로·URL 등)이다. `data/통계표_메타데이터.jsonl`(2,364표)에는 분류 계층(lvl, upItmId, leaf)·항목·시점 목록이 있고 수치는 없다. 단위 칸이 빈 표가 879개(37%)다. 대상 표의 수치는 `notebooks/kosis_fetch_tables.ipynb`로 표 ID를 지정해 KOSIS OpenAPI에서 한 번 받아 파일로 저장한다(형식 B, `data/raw/kosis/`). 이 노트북은 T0-02 범위와 겹치므로 담당자와 공유한다.
2. **대상 표 선정 (3~5개)**: 실전 1 질문 5종(단순 수치·추이·비교·구성비·최대최소)을 모두 만들 수 있게 고른다.
   - 필수 1개: 분류 2단 이하, 연 단위, "계" 포함 (B0 대상 표 겸용)
   - 나머지에서 최소 1개씩: 다른 단위(%, 가구, 천명 등), 결측·비공개·잠정 기호가 있는 표, 분류 3단 이상 또는 연령 구간이 겹치는 표(계/소계/leaf 구분 확인), 월·분기 주기 표
3. **표마다 같은 항목을 측정**한다. 새 파서를 만들지 않고 B0의 `kosis_chat` 로더·전처리(`load_table` → `clean`의 value/value_flag)를 그대로 돌려 결과를 집계한다. B0에는 계/소계 판정(R2)이 아직 없으므로, 분류 계층은 공유 메타데이터 jsonl의 `lvl`·`upItmId`·`leaf`로 붙인다.
   | 항목 | 대응 | 측정 |
   | --- | --- | --- |
   | 입력 형식 | T1-05 | 파일 형식·인코딩, 가로/세로, 응답 필드명(C1_OBJ_NM 등), 분류 계층 메타 유무, 로더 통과 여부 |
   | 크기 | R7 | 셀 수, 항목 수, 분류 단계 수, 단계별 코드 수, 직렬화 시 토큰 수(대략) |
   | 분류 체계 | R1, R2 | 분류명, 코드↔이름, 계·소계·묶음 구간(예: 15~64세) 여부와 위치 |
   | 시점 | R3 | 주기, 시작~끝, 빠진 시점, 표기 형식 혼재(연·월) |
   | 단위·측정 종류 | R5, T1-07 | 항목별 단위, 항목 간 단위 혼재, 배수 단위(천명 등), measure_kind(stock/flow/ratio/index), 소수 자릿수·반올림 |
   | 값·결측 | R4 | 숫자 파싱 비율, value_flag별 빈도(`-`, `x`, `…`, `p`, `e`, 빈 값), 해석 불가 문자열 |
   | 빠진 조합 | R6, T1-08 | 시점×분류 조합 중 셀이 없는 비율 (거절 사유 "표에 없는 조건"의 근거) |
   | 합계 정합성 | R8, R9 | leaf 합 = 계 인지 (차이·반올림 오차), 구성비 표의 분모 존재 |
   | 질문 가능성 | T1-02 | 표별 질문 5종(단순 수치·추이·비교·구성비·최대최소) 가능 여부 매트릭스 (추이 시점 수, 구성비 분모 등) |
4. 결과를 `docs/eda.md`에 표별 한 절 + 표 간 비교표로 쓰고, 마지막에 **다음 태스크에 넘길 것**(T1-02 질문 유형 후보, T1-05 정규화 규칙 수정점, T1-03 골든셋 정답 검증 포인트)을 정리한다.
5. 원본 데이터와 숫자 값 자체는 레포에 커밋하지 않는다(`data/`는 ignore). 문서에는 구조·통계(개수·비율)와 출처(조사명·표명·표 ID·링크)만 쓴다.

## Option A — 노트북 수작업 관찰
- 접근: `notebooks/eda.ipynb`에서 pandas로 표를 하나씩 열어 보고, 관찰한 내용을 `docs/eda.md`에 손으로 정리한다. B0 로더는 쓰지 않는다.
- 예상 성능 향상: 지표 없음. 다음 단계 영향(가정, 데이터 전) — 표 3개의 구조 파악, 정규화 규칙의 큰 누락 발견.
- 실질 반영 이점: 가장 빠름(반나절). 표를 직접 보며 질문 유형 아이디어를 얻음.
- 비용·리스크: 표마다 보는 항목이 들쭉날쭉해지기 쉽고, B0 규칙(R1~R9)이 실데이터에서 맞는지는 따로 확인해야 함.

## Option B — 노트북 + B0 로더·전처리 결과 집계
- 접근: `notebooks/eda.ipynb`에서 표마다 B0 `load_table` → 전처리를 돌리고, 결과(value_flag, 단위, 시점)와 메타데이터의 분류 계층을 pandas로 집계하는 셀을 둔다. 해석은 `docs/eda.md`에 쓴다. 새 모듈·파서는 만들지 않는다.
- 예상 성능 향상: 지표 없음. 다음 단계 영향(가정, 데이터 전) — 위 측정표 9개 항목을 표 3~5개에 같은 기준으로 적용, R1~R9 중 실데이터에서 깨지는 규칙을 건수로 제시.
- 실질 반영 이점: 데이터 정확성·예외 처리. B0 코드가 실데이터에서 처음 검증됨. 측정 셀은 T1-05에서 정규화 모듈로 옮길 때 그대로 참고.
- 비용·리스크: 반나절~하루(10/22 마감 안).

## Option C — 재사용 프로파일러 스크립트 + pytest
- 접근: `scripts/eda_profile.py`에 측정 함수를 따로 만들고 가상 표로 pytest를 쓴다. 표가 늘면 명령 하나로 다시 돌린다.
- 예상 성능 향상: 지표 없음. 다음 단계 영향(가정) — T2-01(표 2,364개)에서 같은 스크립트로 전체 분포를 낼 수 있음.
- 실질 반영 이점: 반복 실행·재현성.
- 비용·리스크: 하루 이상(마감 위험). B0 로더·전처리와 같은 일을 하는 코드를 하나 더 만드는 셈이라 결과가 갈라질 수 있음. 지금은 사용처가 이 태스크 하나뿐이라 CLAUDE.md "필요한 것만 만든다"에 어긋남. 전체 메타 분포는 T2-01(10/29) 범위.

## Recommendation
Option B. 마감 안에 끝나고, 새 코드를 만들지 않고 B0 로더·전처리를 실데이터로 검증하는 효과가 함께 있다. 스크립트화(C)는 T1-05·T2-01에서 실제로 필요해질 때 한다.

## Decision
- 2026-10-21 전민기: **Option B** 선택 (결정 카드 "추천 표 5개 + 옵션 B").
- 수치는 공유 목록에서 표를 골라 KOSIS OpenAPI로 한 번 받아 파일로 저장(`notebooks/kosis_fetch_tables.ipynb`, 표마다 최근 10개 시점). EDA는 저장된 파일만 읽는다(`notebooks/eda.ipynb`).
- 대상 표 5개 (모두 국가데이터처 101):
  | 역할 | 표 ID | 조사 / 표 |
  | --- | --- | --- |
  | B0 기준 표 | DT_1B8000G | 인구동향조사 / 월.분기.연간 인구동향(출생, 사망, 혼인, 이혼) |
  | 비율 단위 | DT_1B26006_A01 | 국내인구이동통계 / 인구이동률 |
  | 월 단위 | DT_1B83A35 | 인구동향조사 / 시도·시군구·월별 혼인 |
  | 다단 분류 | DT_1BPA001 | 장래인구추계 / 성 및 연령별 추계인구 |
  | 단위 빈칸 | DT_1B81A24 | 인구동향조사 / 다태아 여부별 출생 |
- 전체 2,364개 표 수치는 받지 않는다(메타 기준 최소 1.44억 셀, 수십 GB). 필요하면 인구총조사 제외 488개 × 최신 1시점(약 76만 셀)을 따로 검토.
