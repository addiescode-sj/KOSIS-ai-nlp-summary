## Idea
1. 옛 브랜치에서 `docs/question_types.md`만 가져온다(`git show 1d026d9:docs/question_types.md`). 나머지 파일은 가져오지 않는다.
2. 문서의 규칙(§1~§3 판정 조건·경계 규칙)은 승인된 Option B 그대로 둔다. Context 1~6을 현재 master에 맞춘다. §3.2는 grade.py의 실제 동작(`missing_aux` PARTIAL)으로 고치고, golden.py 제약·오류 유형 표를 §0에 더한다.
3. 옵션은 **정본(코드·골든)과 문서를 어떻게 맞추는지**에 따라 갈린다.

## Option A — 사본 수정 (문서에 값을 옮겨 적음)
- 접근: Idea 1~2를 한다. 코드 목록·분포 건수·실례 값을 지금 master 값으로 문서에 다시 적는다. 실례 값은 Parquet에서 한 번 계산해 대조한다(일회성 스크립트, 커밋 안 함).
- 예상 성능 향상: 끊긴 참조 5 → 0. 문서↔정본 불일치(Context 1~7)는 지금 0이 되지만, 이후 어긋나도 검출할 방법이 없다.
- 실질 반영 이점: 산출물① 제출, T1-06·T1-08 명세 확보. 문서만 읽어도 모든 값이 보인다(발표용).
- 비용·리스크: 1~2시간. 이번 사고(코드는 바뀌었는데 문서는 그대로)가 같은 방식으로 다시 생길 수 있다.

## Option B — 정본 링크 + 실례 재계산 테스트
- 접근: 문서가 코드에 있는 값을 **복제하지 않는다.**
  - §0 코드 목록과 §5 분포 건수는 `schemas.py`·골든 파일·하네스 리포트로 링크한다.
  - 문서에는 각 코드의 판정 조건·기대 응답·경계 규칙만 둔다(사람이 판단하는 부분).
  - 손으로 적은 실례 값만 테스트로 지킨다. `tests/test_question_types_doc.py` 1개가 두 가지를 확인한다.
    (1) 골든 notes의 `question_types §x.y` 참조가 모두 문서에 있는 절이다.
    (2) 문서의 실례 원값·파생값을 Parquet에서 `normalize.fetch_table`로 다시 계산해 일치한다. 실례 목록은 테스트 안에 (표, 셀, 식, 기대값)으로 둔다.
- 예상 성능 향상: 끊긴 참조 5 → 0. 문서 실례 수치 중 Parquet으로 재검증된 것 0 → 전부(약 15개). 사유 코드나 골든 분포는 문서에 사본이 없으니 어긋날 수 없다.
- 실질 반영 이점: 데이터 정확성(문서 숫자도 코드가 계산한 값만 남김, CLAUDE.md §2 원칙)과 결과 검증. 이미 있는 `tests/test_schemas.py`의 enum 검사와 겹치지 않는다.
- 비용·리스크: A + 1시간. 문서만 읽으면 건수가 보이지 않으므로 링크를 따라가야 한다. 실례 셀을 테스트에 손으로 지정해야 한다.

## Option C — 사본 수정 + 블라인드 재라벨 측정
- 접근: A + 독립 서브에이전트가 **문서만 보고** 골든 62문항의 질문 원문에 kind/type/refusal_reason을 붙인다. 이를 골든 라벨과 비교한다. 불일치는 원인을 (a) 문서 규칙 부족 (b) 골든 라벨 오류 (c) 재라벨 실수로 나눈다. (a)는 문서를, (b)는 골든을 고치고 다시 잰다.
- 예상 성능 향상: 블라인드 재라벨 일치(kind·type·reason 셋 다 맞음) 미측정 → 수정 후 ≥59/62 목표. 근거: 옛 plan의 목표 불일치율 ≤5%(≤2/40)를 62문항에 적용하면 불일치 3건 이하다. 이 값은 측정한 적 없는 목표치이고, edge 22문항이 복합 질문이라 1차 측정값은 이보다 낮을 수 있다.
- 실질 반영 이점: 질의 이해·결과 검증. "기준 문서가 라벨을 재현한다"는 것을 수치로 남긴다(발표·포트폴리오). T1-06 분류기의 비교 기준(사람 수준 일치율)이 된다.
- 비용·리스크: A + 2~3시간, 서브에이전트 1~2회. 골든 라벨을 고치면 T1-04·T1-19 oracle을 다시 실행해야 한다. 재라벨자도 LLM이라 문서 품질과 LLM 해석력이 섞여 측정된다. A의 사본 어긋남 문제는 그대로 남는다.

## Recommendation
**Option B.** 이번 문제의 원인은 규칙 품질이 아니라 문서가 코드 값을 복제해 두고 따로 움직인 것이다(머지 누락, 분포·출처 어긋남). B는 복제를 없애서 원인을 막고, 남는 손 기록 숫자(실례)는 코드가 다시 계산해 지킨다. 비용도 A와 비슷하다. C의 재라벨 측정은 가치가 있지만, T1-06(질의 분류) 평가와 같은 측정이므로 T1-06 baseline에서 함께 하는 편이 중복이 적다.
