- D1 실전 1이 표 여러 개를 직접 받음. D2 최대 3표. D3 다중 표는 LLM 계획(analyze-plan)만, 규칙 계획은 표 1개 전용.

## 설계
- 표 1개 경로는 건드리지 않는다: 다중 표는 별도 그래프(`graph/build.py build_multi_graph`)와 `MultiStatPipeline`, 공통 단계(compose_llm·verify·template·chart)는 그대로 재사용.
- 자원: `MultiResources(tables)` — 표마다 지금의 `StatResources`(정리·색인·캐시), `primary`=첫 표.
- 판정: 질문 단위 규칙(원인·평가·범위 밖)만 한 번. 표에 없는 시점·칸은 계획 계산 단계가 거절한다.
- 계획: `analyze-plan-multi-v1` 프롬프트, 표별 분류 목록을 `[표 A]`·`[표 B]`로, select마다 `table`(A/B/C 또는 tbl_id) 필수, 모든 표에서 select 1개 이상.
- 계산: `run_plan(..., tables=)` — select는 `step.table`의 표에서, 셀 읽기는 source_ref의 tbl_id로 표를 찾음. 표가 다른 두 값의 combine은 배수 단위면 derivation에 배수를 넣어 환산(`f1 * 1000 - f2`), per는 단위가 달라도 허용.
- 답: 출처 여러 개(`sources`, 답 끝 출처 줄에 표마다), 주의 문구는 표 전체 셀 기준.

## 단계
- S0 plan·기준선 / S1 입력·자원·계산 엔진 / S2 계획(LLM)·판정·그래프·파이프라인 / S3 출처 계약·답 / S4 StatModule·API / S5 dev 평가·문서

## 구현 (단계별 커밋)
| 단계 | 내용 |
|---|---|
| S1 | `compute/plan_engine.py` `run_plan(tables=)`: select는 `step.table`의 표, 셀은 source_ref의 tbl_id로 표를 찾음. 표가 다른 두 값의 combine·share는 `compute/scale.py`로 배수 단위를 환산 사실(`f2 * 1000`, note "천명→명 환산")로 맞춤. per·ratio·index는 다른 기본 단위 허용, diff 등은 `unit_mismatch`. 표 사이 share는 시점만 검사(`semantics.check_share_periods`). |
| S2 | `judge/rules.py judge_multi`(원인·평가·범위 밖·어느 표에도 없는 시점만), `analyze/multi.py` + 프롬프트 `analyze-plan-multi-v1`(표 A·B·C 분류 목록, select마다 table, 모든 표 읽기 검사, 한 번 되돌려 말하기), `graph/multi.py`(compose_llm·verify·template·chart 노드 재사용), `pipeline.MultiStatPipeline`. 계획 실패·형식 오류는 거절(`class_mismatch`), 모델 호출 실패(timeout·api_error)만 RuntimeError. |
| S3 | `StatAnswer.sources: list[Source]`(표 1개면 빈 목록, 여러 개면 `source`=첫 표), 답 끝 출처 한 줄에 표 전부. 템플릿은 표가 다른 계산 값을 계획의 note로 부름. `derived_kind`: `* 1000` 이상 per를 "비중" 대신 "비율"로(기존 버그, LLM 계획에서만 생김). |

| S5 | dev 27문항 `eval/dev/multi_table_dev.jsonl`(`scripts/build_multi_dev.py`가 Parquet에서 pandas로 정답 계산), 채점·실행 `python -m eval.multi_dev --backend oracle|mock|hcx`. |
