## Idea
1. 위 카탈로그의 미커버 함정 10종 + 기존 함정의 **복합 질문**(함정 2개 이상 또는 fact 3개 이상 + derivation)을 후보로 고른다.
2. 각 후보마다 실제 Parquet(`data/values/`)에서 셀을 찾아 `source_ref`로 정답 fact를 만든다. 숫자는 손으로 쓰지 않고 스크립트가 셀 값을 읽어 채운다(`eval/golden.py` `check_facts`가 다시 대조).
3. 신규 문항은 **별도 파일 `eval/golden/stat_golden_edge.jsonl`**에 쓴다. `load_items`는 폴더를 넘기면 `*.jsonl`을 모두 읽으므로 하네스·run_eval은 그대로 쓸 수 있고, 팀 정본 `stat_golden.jsonl`과 충돌하지 않는다. `scope`는 팀원의 `scripts/golden_to_parquet.py`로 채운다. 신규 source fact는 `verify_checklist.md`에 확인 안 된 행으로 추가한다(KOS-54 웹 대조 대상).
4. 커버리지 기록: `eval/harness.py` 리포트에 `eda_trap`별 PASS/FAIL 분해를 추가하고(옵션 B/C), 커버리지 표를 이 plan `## Result`와 `docs/eda-full.md` 4절 골든셋 행에 남긴다.
5. 재실행: oracle 채점(`--oracle`)으로 골든·데이터·채점기 일치 확인 → HCX 실행(`eval.run_eval --scope oracle`)으로 기존 40문항 대비 신규 문항 정답률을 비교한다.

## Option A — 기존 5개 표 안에서 복합 질문 추가 + 일회성 집계
- 접근: 지금 쓰는 표 5개로 만들 수 있는 함정(동부/읍부 합산, 센서스 5년, dash, 소계, 최근 시점, 음수)을 2개 이상 묶은 복합 질문 10~12개 추가. 하네스는 바꾸지 않고 `grades.jsonl`을 `eda_traps`로 묶는 일회성 집계(plan에 결과 표만)로 커버리지를 기록.
- 예상 성능 향상: 함정 커버리지(측정 가능 17종 기준) 9/17 → **~10/17** (5개 표에는 `label_reuse`·`projection_year`·`asterisk_symbol`·월 주기·`mixed_units`가 없음). 문항 40 → ~51, 사용 표 5 그대로.
- 실질 반영 이점: 데이터 정확성(합산 함정) 평가 강화. 새 표·해시 작업이 없어 가장 안전.
- 비용·리스크: 반나절. 표 다양성이 그대로라 "5개 표에만 맞춘 프롬프트" 위험이 남는다. 실전 2 재사용 가치 낮음.

## Option B — 함정별 대표 표 추가 + 하네스 trap 분해 (균형안)
- 접근:
  - 데이터로 확인된 함정마다 대표 표 1개(직접 확인한 후보): `asterisk_symbol` 110_DT_110025_A038_A(`*` 8.4만/10.3만 칸), `mixed_units` 110_TX_11025_A000_A(명/세대 혼재), `sub_annual_period` 101_DT_1B83A35(`1997`·`199701` 혼재), `projection_year`·`no_total_dim` 101_DT_1BPA002 / 101_DT_1BPB301(시나리오), `negative_value` 101_DT_1BPB301 순이동률, `label_reuse` 시군구 표 1개(중구·동구 등, 구현 첫 단계에서 표 확정), `decimal_restore`·`fake_paren_unit`은 위 표에서 해당 셀이 있으면 함께.
  - 문항 18~22개: answerable 복합(trend·compare·share + 함정) ~10, not_answerable ~6, clarify/default_allowed ~4. `eda_traps` 1~3개, `notes`에 함정 설명.
  - 정답 숫자: source fact는 스크립트가 Parquet 셀에서 읽어 채우고, derived fact 값은 같은 스크립트가 `derivation` 식을 pandas로 계산해 채운다(손 계산 없음). 하네스 oracle 채점이 다시 대조.
  - `eval/harness.py` 리포트에 `trap=<태그>` 분해 행 추가(기존 kind/type 분해와 같은 방식, 몇 줄) + 테스트 1개. 매 실행마다 함정별 수치가 남게 하기 위해 일회성 집계 대신 하네스에 넣는다.
- 예상 성능 향상: 함정 커버리지 9/17 → **15~16/17**, 사용 표 5 → **11~13**, 문항 40 → ~60. HCX 정답률은 baseline 없음(로컬에 HCX 실행 결과 없음) → 같은 실행에서 기존 40문항 vs 신규 문항을 나눠 기록하고, 그 차이를 T1-13/14 개선 타깃으로 넘긴다.
- 실질 반영 이점: 데이터 정확성·예외 처리·결과 검증을 함정 단위로 측정. trap 분해는 T1-12·T1-15·발표에서 "어떤 함정에서 몇 → 몇"으로 그대로 쓴다. 표가 다양해 실전 2 검색 골든 후보로도 재사용.
- 비용·리스크: 하루(10/24 마감 안). 새 표 해시는 `golden_to_parquet.py --rehash`로 관리. 외국인주민 표는 10만~30만 행이라 oracle scope가 커질 수 있음 → `scope_report.md`에서 글자 수 확인.

## Option C — 기존 정답 셀 재사용 + 질문 변형(질의 이해 축)
- 접근: 새 셀을 찾지 않고 기존 40문항의 정답 fact를 그대로 쓴다. 질문만 어렵게 바꾼 변형 문항 20개: 줄임말·구어(“부울경”, “작년”, “코로나 직전 해”), 조건 2~3개 결합(“서울·부산 중 2020년 대비 2024년 감소율이 더 큰 곳”), 함정을 숨긴 표현(“읍면동 다 합치면”). 각 변형 문항에 `notes: variant_of=<원문항 id>`.
- 예상 성능 향상: 함정 커버리지는 9/17 그대로(새 함정 없음). 대신 질의 이해 축에서 원문항 대비 변형 문항 정답률 차이를 측정 가능(같은 정답이라 차이가 곧 질의 이해 손실).
- 실질 반영 이점: 평가 기준 3위 "질의 이해"와 슬롯 추출(T1-06)을 직접 겨냥. 정답 검증 비용이 거의 없다(이미 대조된 셀).
- 비용·리스크: 반나절. KOS-59의 "EDA 엣지케이스 반영"과는 거리가 있어 완료 기준을 일부만 충족.

## Recommendation
**옵션 B.** KOS-59 완료 기준("EDA 함정 커버리지 기록")을 직접 채우는 안이고, 데이터로 확인된 함정만 넣어 마감 안에 커버리지를 9 → 15+로 올린다. 스키마를 건드리지 않고 별도 파일이라 팀 정본·KOS-54와 충돌하지 않는다. C의 변형 문항은 T1-06 착수 때 별도로 추가하면 된다.
